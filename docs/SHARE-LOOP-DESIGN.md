# 分享回路设计稿（T3-3.5，一页）

> 状态：设计定稿，未实现。目标：让每一张被分享的卡/每一段被晒出的对话都成为免费获客素材——这是本地部署的 SillyTavern 结构性做不到的事。

## 回路一：角色卡链接分享（优先实现）

**用户故事**：我导入了一张好玩的卡，点「分享」得到一条链接发给朋友；朋友打开链接，卡已经躺在 TA 的肥猫酒馆里，配好 Key 就能聊。

**方案**：卡片 JSON → gzip（CompressionStream）→ base64url → 放进 URL fragment：
```
https://fati-tavern.vercel.app/#card=H4sIAAA...
```
- 用 `#` fragment 而非 query：**数据不会发送到服务器**，隐私承诺不破
- App 启动时检测 `location.hash`，解出卡片 → 弹确认框（显示卡名/头像/分级）→ 一键入库
- 体积预算：普通卡 gzip 后 2–8KB，base64 后 ≈3–11KB；主流浏览器 URL 上限 ≥64KB，超限（世界书巨卡）时降级提示"请用文件分享"
- 18+ 卡分享链接打开时先弹成年确认（复用 contentRating）
- 埋点：`share_create` / `share_open`（漏斗新增一环：分享系数 = share_open / share_create）

**成本**：~1 天（压缩/解压已有基建，UI 两个弹层）

## 回路二：对话片段导出图（次优先）

**用户故事**：聊到一段好玩的对话，选中几条消息导出成一张竖版长图（角色头像 + 气泡 + 底部肥猫 logo + 短链），发到社交平台。

**方案**：Canvas 手绘（不引 html2canvas，保持零依赖基调）：
- 消息多选模式 → 「导出图片」→ canvas 渲染气泡流 → `toBlob` → 下载/系统分享（`navigator.share`）
- 图片底部固定水印区：logo + "fati-tavern.vercel.app" + 卡名
- 埋点：`export_image`

**成本**：~1.5 天（canvas 排版是主要工作量）

## 回路三：只读卡廊（远期，暂缓）

托管一个精选卡片页需要内容审核责任 + 存储，与"不托管、不分发"的 UGC 免责立场冲突。**除非回路一数据证明分享需求旺盛，否则不做。**

## 实现顺序建议

回路一 → 观察两周分享系数 → 决定回路二是否值得做 → 回路三默认不做。
